# PDF 阅读

> **代码位置**：全部在 `index.html` 的 **3b 节**（搜 `3b. PDF 原版阅读器`）。
> 这里**没有** `.js` 副本 —— 早期留过一份做"源码留档"，结果它和内联版本
> 各自演进而失去同步（函数名都不一样了），只会误导后来改代码的人。
> **认准 `index.html`。**

## 定位：像 SumatraPDF 那样看原版式，不重排

PDF 有两种读法，本项目的选择是**看原版式**：

| | 原版式（现在的做法） | 重排成文本（**已废弃**） |
|---|---|---|
| 扫描件 | **直接能看**（看的就是原图） | 必须先跑 30 分钟 OCR |
| 排版 | 100% 还原 | 丢表格/公式/图注/分栏 |
| 文字性 PDF | 能看，还能选中复制 | 能看，但版面信息没了 |
| 实现复杂度 | 中（虚拟化 + 文字层对齐） | 高（坐标重建段落，且永远不完美） |

早期版本做过"重排"路线，实测下来两头不讨好：扫描件要先 OCR，
文字型 PDF 又把版面拆散了。所以**整条重排 PDF 的实现已被移除**，
换成原版阅读器。

> EPUB / TXT 仍然走重排阅读（那本来就是 HTML/纯文本，重排是天经地义的）。
> 两种模式通过 `body.pdf-mode` 互斥切换。

## 高亮：仿生式锚点，只突出少数几个字

**先说硬限制：在 PDF 上做不到"把词首字母加粗"。**
页面渲染到 canvas 之后，文字已经**栅格化进像素**了 —— 没法只把某几个
字母变粗或变大。任何基于 pdf.js 的阅读器都一样，不是本项目的实现问题。

**但"只高亮几个字"完全可以做到**，而且视觉引导作用与仿生阅读等价：

```
┌─ canvas：原页面位图
└─ .pdf-tl：透明文字层
     └─ .pdf-blk   一行文字的容器（保留 pdf.js 的定位）
          ├─ 原 span（visibility:hidden，只为选中/复制保留）
          └─ .pdf-ch × N  每个字一个 span，按像素定位
               其中若干带 .pdf-anchor → 加色带
```

所以看到的效果是**零星的黄块**（每个锚点一个字），而不是整行糊一片底色。

### 锚点怎么选：中文走现有算法，英文单独补一条

**中文**：`computeHanAnchors(text, strength)` —— 与 EPUB/TXT **同一套**规则
（标点切分 + 分词器 + 虚词表 + 间隔表），强度也取自用户设置。
所以在 PDF 上调"高亮强度"，行为和其他格式一致。

**但 PDF 有个特殊之处**：pdf.js 的"块"是按**基线行**切的，
常常是句子中间的片段（`许多潜在的指称对象。有的语言说Ihit`），
不以标点开头。而算法的第一遍"结构锚点"只在标点后/段首触发 ——
于是片段开头的字拿不到锚点，**整块可能 0 个锚点**（实测出现过整行空白）。

两个补丁：

- **块首补位**：块首第一个非标点字补一个锚点 → 每行都有落点，密度均匀
- **块尾去位**：锚点落在最后一个字上时删掉 → 否则色带贴着行右缘，
  看起来像一块悬空色斑

### ★ 英文（拉丁）词：每个词的前 1~2 个字母

`computeHanAnchors` 那套规则是**为汉字设计的** ——
它建立在"中文没有空格、词边界要靠标点和虚词透出来"这个前提上，
所以它只处理"汉字区段"。**拉丁词走过去一个锚点都拿不到。**

实测：纯英文 PDF 每行只有"块首补位"那**一个**孤零零的锚点，
连 `internationalization` 这种长词都完全不标。等于英文 PDF 基本没有高亮。

所以单独补一条拉丁词规则（在 `_pdfSplitBlocksIntoChars` 里）：

| 强度 | 每个词标几个字母 |
|---|---|
| 1 ~ 2 | **1** 个（最克制，只给个起点） |
| 3 ~ 5（默认 3） | **2** 个（锚定感明显又不碎） |

```js
const enLen = strength >= 3 ? 2 : 1;
WORD_RE.lastIndex = 0;                     // 复用同一套词边界定义
while ((m = WORD_RE.exec(text)) !== null) {
  const w = m[0];
  if (HAN_RE.test(w)) continue;            // 汉字交给上面那套，互不干扰
  if (!/[A-Za-z]/.test(w)) continue;       // 纯数字不锚（如 2026）
  const n = w.length <= 2 ? 1 : Math.min(enLen, w.length - 1);
  if (!anchors.has(m.index)) anchors.set(m.index, n);   // 不覆盖已有锚点
}
```

几个刻意的取舍：

- **短词只标 1 个**：`a` / `be` / `to` 若标 2 个就整个词都被标，
  失去"锚点 vs 其余部分"的对比
- **纯数字不锚**：`2026` / `3.14159` 锚上去没有引导价值
- **复用 `WORD_RE`**：不另造正则，保证与其它格式的词边界判定一致
- **不覆盖已有锚点**：块首那个补位锚点可能正好落在某个词首

效果（实测 `english.pdf`）：

```
原文：Bionic reading highlights the beginning of each word so the eye
锚点：Bi     re      hi         th  be        of   ea   wo   so  th  ey
```

中英混排也对：`I hit myself` 里 `Ih` / `my` 会被锚上，
而同一行的汉字仍走中文规则。

### 拆字定位：两个把色带画歪的坑

**(a) 容器宽度不能用 `width:100%`。**
块的长度差异很大（12 字的标题 vs 39 字的正文行）。用 100% 会把短块
拉伸到整页宽，百分比切分随之被放大 —— 实测末字右边界**漂出 353px**，
色带跑到行尾外面。

正解：拆字前用一次 `getBoundingClientRect()` 量出原 span 的真实宽度，
写死到容器上。

**(b) 定位只能有一层。**
早期把原 span 包进一个"继承同样定位信息"的容器，再在容器里切分 ——
结果是定位叠加两次（容器一次、原 span 一次），短块被拉伸。

正解：**整平结构**。量出原 span 相对**父容器**的坐标，在同一层放字容器，
字符位置用**像素累加**（`acc / total * totalW`），不用百分比。

> 为什么可以用"等宽估算"而不是精确测量：
> 逐字量真实宽度需要 `offsetWidth`，每页上千次会强制重排，卡到不能用。
> 而中文本来就等宽（误差近乎 0），西文误差也在半个字以内 ——
> 色带本来就是**近似标记**，不需要像素级精确。

### 全角/半角宽度

`_pdfCharWidth()`：CJK / 全角标点 / 假名 / 韩文 → 1.0，其余 → 0.5。

### 原 span 必须保留

拆字后原 span 只设 `visibility:hidden`，**不从 DOM 移除** ——
否则会失去选中/复制文字的能力（那是文字层存在的另一半意义）。

### 颜色与浓淡可调（设置面板 → "PDF 高亮"）

底色是**压在原图之上**的，浓淡直接决定可读性。
早期把颜色和透明度写死成 `rgba(255,214,0,.55)`，结果"太黄了、妨碍阅读"。
现在两者都可调：

| 项 | 范围 | 说明 |
|---|---|---|
| 高亮色 | 6 种预设 + 任意取色 | 黄 / 绿 / 红 / 蓝 / 紫 / 橙 |
| 不透明度 | 8% ~ 60%（默认 **22%**） | 调高会妨碍阅读，够用即可 |

实现上用**两个 CSS 变量**：

```css
--pdf-hl-rgb    /* "255,214,0" —— 三元组，不是完整颜色 */
--pdf-hl-alpha  /* 0.22 */
body.pdf-hl .pdf-tl span.pdf-anchor{
  background: rgba(var(--pdf-hl-rgb), var(--pdf-hl-alpha));
}
```

> 为什么是"三元组 + 独立 alpha"而不是直接写 `rgba()`：
> "整块高亮"档要把 alpha 再乘 0.75（覆盖面积大，同样浓度会糊住原文），
> 拆开才能用 `calc()` 算。

**改设置立刻生效，不用重开 PDF** —— 色带是 CSS 背景，改变量后浏览器自己重绘，
不需要重建文字层。所以 `applyPrefs()` 里**不应该**出现 `getDocument` /
`_pdfRescale` 之类的调用（测试有断言守着这条）。

设置随其它偏好一起存进 `localStorage`（`bionic.prefs.v1`），
重载后颜色、透明度、选中态、取色器都能恢复。

| PDF 类型 | 能否高亮 |
|---|---|
| 文字型（Word/LaTeX 导出） | ✅ 能 |
| 扫描件 | ❌ 抽不到文字块，无法定位 |
| 扫描件 + 跑过 `ocr/` 脚本 | ✅ 能（补的文字层就是高亮依据） |

**扫描件勾了高亮也不会有反应** —— 这是正常的，不是坏了。
界面会明确告诉你原因：工具栏的开关旁边会显示 **「（本页无文字层）」**，
鼠标悬停有完整说明和解决办法。

## 关键实现点（改代码前先读）

### 1. ★ 必须做"可视区渲染"，否则必崩

一本 325 页的书，每页一张 canvas（约 1200×1700，dpr=2 时更大）≈ 8MB 位图。
全渲染就是 **2.6GB** —— 页面直接崩掉。

所以：

- **占位盒先建**（`_pdfBuildPlaceholders`）：按每页真实尺寸建 `div`，
  只算尺寸不画像素。这样滚动条长度是对的，页码跳转才有目标。
- **`IntersectionObserver` 驱动**（`_pdfSetupObserver`）：进入视口附近的页
  才渲染，离开就 `_pdfUnrenderPage` 销毁 canvas、恢复占位。
- **`rootMargin: '120% 0px 120% 0px'`**：上下各留一屏缓冲，
  快速滚动时不会看到大片空白。
- 实测：325 页的书，同时存活的 canvas **只有 2~3 张**。

占位盒必须写 `flex:0 0 auto`，否则在 `display:flex` 的容器里会被压扁，
滚动高度就错了。

### 2. ★ 中文 PDF 必须给 cMaps

中文 PDF 几乎都用 **Type0 复合字体 + `UniGB-UCS2-H` / `UniGB-UTF16-H`** 编码
（一个字符用 2 字节 CID）。**pdf.js 不内置这些 CMap**，必须通过 `cMapUrl` 指过去。

不给的后果：

- **不报错**
- 英文 PDF 看着一切正常
- 中文 PDF **整页抽出 0 个字符**

实测：一本带文字层的 PDF，不加 `cMapUrl` 时 325 页**全部** 0 字符，
加上立刻恢复。**这个现象和"这是扫描件"长得一模一样** —— 排查时极易误判。

### 3. CDN 回退列表里只能放 ESM

`import()` **不能执行 UMD 构建**（`pdf.min.js`），会以
"Failed to fetch dynamically imported module" 失败。它常排在列表最后，
看起来像"所有 CDN 都挂了"，实际是格式不对。

- ESM 列表只放 `.mjs`
- 真要回退 UMD，得用 `<script src>` 注入（见 `_loadPDFJSViaScript`）

另外 **worker 必须和主库同版本**，pdf.js 会校验，不一致直接报错。

### 4. ESM 模块命名空间是冻结的

`lib.__version = v` 会抛 `Cannot assign to property`。
版本号单独用变量存（`pdfjsVersion`）。

### 5. 空文字块必须藏掉

`TextLayer` 会产出宽度为 0 的**分隔用 span**。给它们加底色会在页面上
画出莫名其妙的零星色点。所以渲染后要：

```js
if (!(d.textContent || '').trim()) d.style.display = 'none';
```

### 6. 文字层探测：抽样只是"参考"，真正的依据是**逐页实测**

打开时按"均匀取 20 页"抽样，**只用来决定提示文案**，不作为功能开关。

两个必须守住的点：

**(a) 不能用抽样禁用高亮开关。**
实测踩过 —— 一本只有 4 页被 OCR 补过文字的书（45/46/61/66 页），
20 页均匀抽样**全部落空**，于是开关被错误置灰，用户以为功能坏了。

现在开关**始终可用**：真有文字块的页显示色带，没有的页什么都不画，没有副作用。

**(b) 抽样没命中时，提示里不能说"这是扫描件"。**
同样是那本书，抽样全落空，早期文案直接断言"多半是扫描件" ——
明明不是。现在改成"抽样暂未发现文字层，翻几页看看有没有黄色高亮即可确认"。

**真正的依据是逐页实测**：每渲染一页就统计 `textSeenPages / renderedPages`
（`_pdfUpdateHlHint`），只增不减。据此：

- 找到过文字 → 提示"已找到 N 页含文字"
- 翻过 3 页以上且一个文字块都没有 → 才判定为纯扫描件，
  并在开关旁显示 **「（本页无文字层）」**，tooltip 里指出用 `ocr/` 补文字层

> 教训：**不要用一次抽样给整本书下结论**，尤其不要用它禁用功能。
> 抽样只适合给"预期"，实测才配给"结论"。

### 7. 进度要分两套存

重排书的进度是 `{chapter, ratio}`，PDF 是 `{page}` —— 语义不同，
混在一个键里会互相覆盖。所以 `PROGRESS_KEY` 与 `PDF_PROGRESS_KEY` 分开，
后者只保留最近 20 本。

### 8. 工具条选择器别和既有规则撞车

给 PDF 模式加显隐时，如果写出裸的 `#pager{display:none}`，
它会**先于**真正的 `#pager{...}` 规则出现，把按"第一个匹配"取规则的
检查（`tests/test-home-glass.mjs` 用非贪婪正则）引到错误的地方。
所以显隐规则一律带 `body.pdf-mode` 前缀，且**保持每个选择器只定义一次**。

（测试侧也补了行首锚定 `^\s*sel\s*\{`，两边都加固。）

### 9. ★ 别把「设置面板」当成"PDF 无关"而禁用

PDF 下确实有一批控件无效 —— 加粗/变色做不到（文字已栅格化），
字号/行距/每行宽度也无意义（那是重排阅读的参数）。

但**不能顺手把设置面板一起禁用**。踩过这个坑：

```js
// ✗ 错误：把面板和仿生开关一起禁掉
['#btnBionic', '#btnPanel'].forEach(s => { $(s).disabled = true; });
```

后果是用户**根本打不开设置**，而 **PDF 高亮的颜色和不透明度就在那个面板里**
—— "设置点不进去，就没法调高亮颜色"。

**正解分两层：**

| 对象 | 处理 | 理由 |
|---|---|---|
| `#btnBionic` | **禁用** | 它是二态开关，PDF 下加粗做不到，留着会误导 |
| `#btnPanel` | **保持可用** | 面板里还有 PDF 高亮设置，禁掉等于把用户锁在门外 |
| `#bionicSec` / `#typesetSec` | 用 CSS 隐藏 | 无效的小节收起来，但面板本身照常打开 |
| `#pdfHlSec` | **不能隐藏** | 这是 PDF 下唯一有用的那一节 |

隐藏用 `body.pdf-mode #bionicSec{display:none}`，**不是从 DOM 删节点** ——
切回 EPUB/TXT 时要原样恢复（实测来回切换状态正确）。

> 这条最初还被**测试锁错了**：有条断言写的是"PDF 模式下禁用仿生/排版入口"，
> 把 bug 当成了预期行为。改代码时要留意 ——
> **断言"某个东西被禁用"之前，先确认禁用是用户想要的**。

## 功能与快捷键

| 操作 | 快捷键 |
|---|---|
| 上一页 / 下一页 | `↑` `↓` `PgUp` `PgDn` `空格` |
| 首页 / 末页 | `Home` / `End` |
| 放大 / 缩小 | `+` / `-` |
| 回首页 / 换书 | `H` |

工具栏还提供：适应宽度、适应整页、页码输入框直接跳转、文字高亮开关。

- 阅读进度按文件记忆（文件名+大小+修改时间做 key），下次打开自动跳回
- 缩放模式：`适应宽度`（默认）/ `适应整页` / 手动缩放（`+`/`-` 后进入）
- 窗口尺寸变化时，适应模式会自动重算
- PDF 模式下**仿生阅读与排版面板被禁用** —— 文字已栅格化，那些参数没有意义

## 已知限制

- **不做 OCR**。扫描件能看但**不能高亮**（抽不到文字块）；
  要高亮请先用 `ocr/` 的脚本补文字层
- **双栏/多栏 PDF** 的文字层按 pdf.js 的给法逐块渲染，
  高亮块可能与阅读顺序不完全一致（但位置是对的）
- 表格、公式没有"文字块"的细分，高亮会覆盖整行
- 需要联网加载 pdf.js（约 350 KB）与 cMaps（按需拉取）
- 超大文档（上千页）首次打开时，抽页尺寸会有可感知的等待
